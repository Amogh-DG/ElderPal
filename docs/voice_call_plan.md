# AI Voice Call Integration Plan (Fall & SOS Alerts)

## Overview
When a fall or SOS is triggered, `EmergencyAlertManager` generates an alert message via `AlertMessageBuilder` (containing alert type, time, last medicine taken, and Google Maps location link). This plan outlines how an Android phone can trigger a cloud function to place an automated AI voice call via Twilio to read that message aloud to the primary emergency contact.

---

### 1. Exactly What Accounts, Services, and Settings Are Needed

1. **Twilio Account**:
   - **Twilio Programmable Voice** enabled.
   - **One Twilio Phone Number** with Voice capabilities (typically a US/international local number, e.g., `+1-xxx`, because Indian domestic numbers are not available for standard self-service outbound calling).
   - **Voice Geographic Permissions**: In the Twilio Console under *Voice > Settings > Geo Permissions*, **India (+91)** (and any other target country) must be explicitly enabled. It is blocked by default on new accounts.
   - **TwiML Configuration**: A TwiML response using the `<Say>` verb (e.g., `<Say voice="Polly.Aditi">` for clear Indian English pronunciation) to speak the message text passed to the call.

2. **Cloud Function Host (e.g., Firebase Functions / Google Cloud Functions)**:
   - A serverless project (Node.js or Python) hosting a single HTTPS endpoint (e.g., `triggerEmergencyVoiceCall`).
   - Official Twilio SDK installed (`twilio` npm or python package) to initiate the call via Twilio's REST API (`client.calls.create`).

3. **Android Client Settings**:
   - `android.permission.INTERNET` in `AndroidManifest.xml`.
   - An HTTP client (e.g., OkHttp / Retrofit) to send the POST payload containing recipient phone number and the text generated by `AlertMessageBuilder`.

---

### 2. Secret Storage and App Authentication

- **Where Secrets Live**:
  - `TWILIO_ACCOUNT_SID` and `TWILIO_AUTH_TOKEN`: Stored **exclusively in Cloud Function environment secrets** (e.g., Firebase Functions Secrets or Google Cloud Secret Manager).
  - **Never** place Twilio credentials or server API keys inside the Android app, `local.properties`, git, or any public repository.
- **How the App Authenticates to the Cloud Function**:
  - To prevent strangers from invoking the Cloud Function and running up bills:
    1. **Firebase App Check (Recommended)**: Integrates Google Play Integrity API to cryptographically prove that incoming HTTP requests originate from the genuine, unmodified ElderPal app installed on a real device. The Cloud Function verifies the `X-Firebase-AppCheck` token and rejects all unauthorized traffic.
    2. **Firebase Anonymous Authentication**: Authenticates the device session and supplies a short-lived Firebase ID token in the `Authorization: Bearer <token>` header.
    3. **Cloud-Side Payload Sanitization & Rate Limiting**: The Cloud Function limits call frequency (e.g., maximum 3 calls per hour per recipient number) and restricts message length (max 300 characters) to prevent abuse even if an authenticated token is used.

---

### 3. Twilio Trial Limits and Callable Numbers

- **Trial Balance**: Twilio provides ~$15.00 in free trial credit (~75 voice minutes).
- **Callable Numbers**: 
  - **You can ONLY call Verified Caller IDs** on a trial account.
  - You cannot call arbitrary family numbers unless you first verify each number in the Twilio Console (under *Phone Numbers > Manage > Verified Caller IDs*) using an SMS OTP.
  - Maximum of **5 verified phone numbers** allowed on a trial account.
- **Mandatory Trial Audio Disclaimer**:
  - Every outbound call on a trial account plays an unskippable Twilio disclaimer ("You have a trial account. You can remove this message by upgrading to a full account... Press any key to continue") before reading your message. This introduces a major delay for emergency alerts until the account is upgraded.
- **Number Limit**: Trial accounts can purchase only 1 active trial phone number.
- **Trial Expiration**: Unused credits expire after 30 days unless upgraded.

---

### 4. India-Specific Rules for Calling Indian Numbers (+91)

- **No Local Indian Outbound Numbers**: Twilio does not offer local Indian (+91) numbers for self-service outbound calling. Calls to Indian numbers will display an **international caller ID (e.g., a US +1 number)**. Family members may ignore or reject the call thinking it is international spam unless instructed in advance to save the number.
- **Voice Geo-Permissions**: Twilio accounts have outbound calling to India turned OFF by default; you must manually enable it in Twilio Voice Geo Permissions.
- **TRAI Regulations & DND (Do Not Disturb)**:
  - Commercial and automated promotional calls are governed by TRAI under TCCCPR rules and blocked on numbers registered with the National DND registry.
  - *Emergency alert uncertainty*: While personal transactional emergency alerts to family contacts are technically legitimate non-promotional communications with prior consent, **I'm not sure** whether Indian mobile carriers (such as Jio, Airtel, or Vi) will consistently route automated VoIP text-to-speech calls from an international number without occasionally flagging or dropping them under automated spam/DND filters.
- **Voice OTP Restrictions**: Twilio explicitly prohibits and carrier routes often block international automated voice OTPs into India; while this is an alert rather than an OTP, automated text-to-speech from foreign numbers faces scrutiny.

### 5. Data Leaving the Phone and Privacy Statement Impact

- **What Data Leaves the Phone**:
  - The primary contact's phone number.
  - The elder's exact GPS coordinates and Google Maps link (`https://maps.google.com/?q=lat,lng`).
  - Sensitive health data: The name, dosage, and time of the last taken medicine (e.g., *"Blood Pressure pill at 3:45 PM"*).
  - Alert context: Alert trigger type ("Fall detected" or "SOS pressed") and exact timestamp.
- **Impact on Privacy Statements**:
  - **Current Spec**: The current spec states that all medicine and schedule data stays local on the device, with no cloud storage of health data.
  - **Required Updates**:
    1. **Disclose Cloud Transmission**: The privacy notice and in-app permissions screen must explicitly state that when a fall/SOS occurs, health context (recent medicine taken) and exact location are sent over the internet to a cloud backend and third-party telecom provider (Twilio).
    2. **Third-Party Data Retention**: Twilio automatically retains call detail records (CDRs)—including destination numbers, call durations, and call timestamps—in account logs.
    3. **Explicit In-App Consent**: Add a setting or toggle on the Emergency Contacts screen ("Enable automated AI voice call") so the elder or family explicitly consents to sending this data off-device.

---

### 6. What Could Fail and Fallback to Native SMS and Direct Call

- **Potential Failure Points**:
  - **No Internet Connectivity**: The elder's phone lacks Wi-Fi or mobile data (common in basements or after battery-saver mode kicks in).
  - **Cloud Latency / Cold Starts**: Serverless functions can take 5–10 seconds to cold-start.
  - **Twilio API Failure**: Insufficient trial credits, unverified destination number, or carrier-level call blocking.
  - **Family Member Action**: Contact's phone is busy, off, or the contact declines an unfamiliar international call.
- **Fallback Strategy**:
  - **Never block the native alert pipeline**: Cloud voice calling must run **asynchronously in parallel** without delaying the existing local SMS and phone call.
  - **Step-by-step sequence in `EmergencyAlertManager`**:
    1. **Immediate Local SMS**: Send native SMS via `SmsManager` to all contacts immediately (operates over cellular voice/SMS signaling even with weak/no mobile data).
    2. **Async Cloud Voice Request**: Dispatch the HTTPS call to the Cloud Function in a background coroutine with a strict **5-second timeout**.
    3. **Automatic Fallback to Direct Phone Call**: 
       - If the cloud request times out, fails, or throws an exception, immediately fall back to the existing native phone call logic (`CALL_PHONE` or opening the system dialer).
       - Even if the cloud call successfully initiates, the app should still present or place the local phone call as the guaranteed audio link between elder and family.
    4. **Graceful Reporting**: Record the cloud voice call outcome (e.g., `CLOUD_CALL_DISPATCHED`, `CLOUD_CALL_FAILED`, or `SKIPPED_OFFLINE`) in `AlertDispatchReport` without throwing unhandled exceptions.

### 7. Rough Cost Estimate and Pre-Reliance Checklist

- **Cost Estimate**:
  - **Cloud Function**: Free tier on Google Cloud / Firebase covers up to 2 million invocations per month ($0.00).
  - **Twilio US Phone Number**: ~$1.15 / month (fixed recurring cost).
  - **Twilio Outbound Voice Call to India**: ~$0.05 / minute (partial minutes rounded up to full minute; ~₹4.20 INR).
  - **Text-to-Speech (`<Say>`)**: ~$0.0008 to $0.0032 per 100 characters for Amazon Polly / Google neural voices (~$0.0001 per alert; basic robotic voice is free).
  - **Total Cost per Emergency Alert**: **~$0.05 to $0.06 per incident** (~₹4.50 to ₹5.00 INR), plus the monthly **$1.15** number rental.
- **What to Check Before Relying on It**:
  1. **Trial Audio Delay**: Verify in testing how much delay the trial disclaimer introduces before the emergency message plays.
  2. **Caller ID & Spam Filtering**: Call your own and test family numbers from the Twilio number to verify if Truecaller or Indian carriers mark it as spam, and have family save the Twilio number to their contacts.
  3. **Auto-Recharge Balance**: Before relying on this for a real emergency, upgrade from trial and enable auto-recharge so calls never fail due to zero credit.
  4. **Voicemail / Answering Machine Handling**: Test what happens if the contact does not answer and the call goes to carrier voicemail.
